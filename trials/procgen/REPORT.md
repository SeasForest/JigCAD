# 试验：用 JigCAD Skill 复刻 procgen-hy4 的模型

> 第二轮（city-gate，多材质）见文末「city-gate 与多材质」。

日期：2026-11-23。对象：[procgen-hy4](https://github.com/wrong-nebula/procgen-hy4) 中的 4 个模型。
做法：严格按 `skill/jigcad/SKILL.md` 的流程，以 Agent 身份编写规格，记录每一轮迭代。
procgen 用米，这里统一换算为毫米，派生尺寸照搬原文件的公式。

## 迭代日志（每个失败是谁的错，自检有没有拦住）

| 模型 / 轮次 | 报告 | 根因 | 归属 | 处理 |
|---|---|---|---|---|
| plummer 1 | `kernel TypeError` | `boss.hole_depth` 不支持 `next`，而且组件代码异常被错标成 `kernel` | **JigCAD bug** | 已修复；新增 `internal` 错误码 |
| plummer 2 | `disjoint`，后改为 `touch_only` | 油杯放在圆柱外壳的 `top` 上，只有线接触 | 建模错误（Agent） | 新增 `touch_only` 诊断，fix 提示"往里埋 s mm"；照做后通过 |
| clevis 1 | `floating` | `flip` 让 v 轴反向，眼孔被放到 z = -80 | 建模错误（Agent） | floating 报文改为附带工具和本体包围盒；SKILL 写明 flip 规则 |
| clevis 2 | `bbox.size_y` | 叉耳（2·r_eye）比连接段宽，是我的检查值写错了 | 检查写错（Agent） | 改正检查 |
| turntable 1 | `floating` 吊杆 | `profile` 拉伸方向依赖顶点绕向，顺时针时反向 | **JigCAD bug** | 已修复：自动规范为逆时针 |
| turntable 2 | `manifold` 全局失败 | 车轮与环轨线接触，熔合后非流形；全局检查定位不到特征 | 建模错误，加 **JigCAD 诊断缺口** | 新增逐特征 `non_manifold` 检查；加 0.5 mm 运行间隙 |
| turntable 2 | `bad index 0` | `cylinder` 等基础组件不输出定位点 | **JigCAD 缺口** | 每个实例默认输出锚点原点 |
| turntable 3 | angle=30 时 `dim` 失败 | 检查用了世界坐标 x，不具备旋转不变性 | 检查写错（Agent），由扫描发现 | 改用到转轴的距离 |
| turntable 4 | angle=270 时 `bbox` 超差 | `rotate` 是原地自转，`at` 不随之旋转；**30° 和 135° 时轨道已经放错但没被发现** | **JigCAD 语义缺口** | 新增 `frame_rotate`，加旋转不变检查 `track_offset` |
| （全部） | 4 个角度的指纹相同 | 指纹只哈希了属性，对称旋转后不变 | **JigCAD 缺口** | 指纹加入顶点坐标哈希 |

统计：

- 共 11 次失败，**全部在本地被自检发现**，没有一次需要靠人眼发现。
- 其中 6 次是 JigCAD 自身的问题（3 个 bug、3 个缺口），都已修复，并补了回归测试（测试数 31 → 39）。
- 另外 5 次是建模者或检查写错，诊断都直接指出了修改点。
- 一个值得警惕的现象：turntable 的轨道错位在 2 个角度下"静默通过"。只有加了**旋转不变的意图检查**再配合**参数扫描**才抓得住。结论写进了 Skill：每个关键关系都要有一条检查，而且要扫描所有控件。

## 与 procgen 的对比

**JigCAD 更强的地方**

- 精确的实体几何（B-Rep），导出 STEP，尺寸能精确到 0.01 mm。轴承座的中心高、螺栓间距、叉口宽度都用 `dims` 检查锁定。
- 规格行数少：系柱 29 行（procgen 52 行）；转车台主体 137 行（procgen 813 行，不过 procgen 的版本细节多得多）。
- 错误定位到具体特征，并给出修改建议；校验全部在本地执行，零 token 成本。
- 改参数后确定性重建：转车台 d 在 10~20 m、angle 在 0~360° 范围内全部通过。

**JigCAD 做不了或做得别扭的地方（转车台暴露的）**

| 缺口 | 影响 | 建议 |
|---|---|---|
| 没有回转体（lathe/revolve） | 钢轨头部截面、带台阶的轴类零件只能用矩形管近似 | **v0.2 必做**：`revolve` 组件（任意截面） |
| 没有装配和多体 | 旋转桥体被迫和静止的坑体熔成一体；车轮和轨道只能留间隙；无法给不同零件分配材料 | **v0.2 必做**：`assembly`，加零件间的接触、间隙、干涉检查 |
| 没有"组变换" | 桥体的 13 个特征都要重复写带三角函数的显式平面（`on: {origin, normal, x_dir}`），冗长易错 | 新增 `frames:`（命名坐标系，可引用、可旋转） |
| 没有两点间杆件 | 风撑、拉杆、扶手无法表达 | 新增 `rod {from, to, d}` |
| 斜置零件 | 斜下弦杆改成了腹板平面内的多边形 | `frame_rotate` 目前只能绕法向转，可扩展为绕任意轴 |
| 表面细节（铆钉、文字、接缝） | 没有做 | 属于视觉层；工程上可做 `text` 雕刻和铆钉阵列 |
| 大场景渲染 | 特征一多标签就重叠，坑壁挡住内部 | **本次已加**：编号标签加图例、`--section x\|y\|z` 剖视 |

## 结论

- 机械和功能件（轴承座、U 形叉、系柱）：JigCAD 适配良好，1~3 轮就能通过，且有精确的尺寸保证。这类模型正是它的定位。
- 场景和机构类（转车台）：能做出准确的主体结构，并通过了参数扫描，但表达成本高，缺少回转体、装配和组变换。
  这三项正是 PRD 路线图中 v0.2 要做的，优先级建议上调。

## city-gate 与多材质（第二轮）

对象：`examples/hy4/city-gate.py`（611 行，Hy4 Flash 生成；Ledoux 风格收费城门）。
用到 6 种 procgen 材质槽：stone、pier-ashlar、chipped-limestone、slate、bronze、copper。

### 为此新增的 JigCAD 能力

| 能力 | 说明 |
|---|---|
| 多材质/多色 | 顶层 `material`（默认）+ `materials:`（自定义颜色/密度）；特征级 `material:`。内置色表包含 procgen 全部槽名（颜色取自 `doc_eval.cpp`），可 1:1 映射 |
| `op: paint` | 只改材质、不改几何：分层色带、券石环、鼓室、logo 皮层 |
| 区域划分 | 几何仍是一个熔合实体（自检照旧），按特征历史切成材质区域，后加的覆盖先加的；体积守恒自检，不守恒则回退精确算法 |
| 多材质导出 | 带颜色的 STEP 装配；3MF（每种材质一个带色对象）；带色 GLB；每种材质一个 STL，供切片软件分配挤出头 |
| 多材质检查 | `materials: N`、`material_at` 颜色探针、`material_hidden`（颜色被完全覆盖）、`material_island`（打印不出的碎色块）、按密度的分材质质量 |
| 新组件 | `revolve`（车削，用于柱身、鼓座、穹顶、尖顶）、`arch`（拱券开口）、`rod`（两点杆件，用于山花斜檐） |
| `repeat` 组合 | `grid`/`points` + `mirror`（门廊柱：左右阵列 × 前后镜像）；`linear`（可沿法向阵列，用于分层色带） |
| 不等式检查 | `dims` 支持 `min`/`max`，以及 `level: warn`（软约束） |
| 渲染 | 按材质着色；`--tile` 出大图 |

### 结果

| 项 | 数值 |
|---|---|
| 规格 | `city_gate.yaml` 405 行（48 个特征）+ 组合组件 `components/tuscan_column.yaml` 22 行；procgen 原文件 611 行 |
| 自检 | PASS 27/27（含 12 个 `material_at` 颜色探针、通道/道路空腔探针、柱距与门廊偏移） |
| 材质占比 | chipped-limestone 52.35%，pier-ashlar 29.47%，stone 16.48%，copper 1.66%，slate 0.03%，bronze 0.01% |
| 控件扫描 | width 11/22 m、height 10/18 m、columns 5/6，单项扫描 6/6 PASS |
| 构建时间 | 第一版 135 s，优化后 42 s（几何指纹不变） |
| 导出 | STEP 8 MB（带颜色）、3MF、GLB、7 个 STL（整体加每种材质一个） |

渲染图：`city_gate.png`（四视图，编号图例）、`city_gate_iso.png`（大图）。

### 过程中发现并修复的问题

| 现象 | 根因 | 归属 / 处理 |
|---|---|---|
| 穹顶报 `non_manifold` | build123d 把回转体尖顶处的退化边误判为非流形 | **JigCAD bug**：两级流形判定（快速检查，出现"否"时再用精确检查复核） |
| 构建 135 s | 灰缝刀具逐实例对全部面求距离；材质划分每段两次大布尔运算；`body.volume` 反复计算；流形检查慢 | **性能**：近邻面预筛；基于历史的局部划分；体积和流形结果缓存；加料检查优先用体积守恒推断 → 42 s |
| 两种划分算法差 0.02% | 精确算法在一个合并着色段上，内核**静默丢失**了布尔结果 | 改为以历史划分为主（不碰大主体），精确算法只作兜底；加体积守恒自检 |
| 单项扫描全过，但宽 11 + 6 柱时柱础互相穿插 | 单实体模型会把相互穿插的同材质零件静默熔合 | **检查盲区**：新增 `dims min`，柱净距 ≥ 0 → 该组合被正确拒绝（原版公式同样有这个问题） |
| 宽 22 + 高 10 时山花高出屋面 1.4 m | 山花高度随宽度、墙高随高度变化，比例失调 | 软约束 `level: warn` 报警告 |

### 与 procgen 版本的差异（简化项）

- 未做：表面细节（ashlar 凿面纹理、接缝、铆钉、"OCTROI" 浮雕字、柱头倒角平滑）。属于视觉层，JigCAD 目前没有 text/rivet 组件。
- 券石：整圈着 pier-ashlar，未做每 4 块交替 limestone。
- 鼓座柱廊：比原版错开 15°。原版的柱子正好挡在窗户正前方，这里改为放在窗间。
- 单实体：原版是多个网格零件，这里熔合成一个实体再按材质分区。所以切片和 STEP 里得到的是"多色单件"，不是"多零件装配"。

### 结论

- 多色已经打通：从规格声明、自检、颜色探针，到 STEP/3MF/GLB/分色 STL 导出，一条链路完整。procgen 的材质槽可以直接沿用。
- city-gate 这种 48 个特征的建筑套件，能在 405 行规格内复现主体形态，并通过全部检查和单项控件扫描。规格行数优势不大（405 对 611），JigCAD 的价值主要在精确几何、可验证和可导出。
- **两个经验**：
  1. 单项扫描不够，控件组合也要扫，并给物理约束（间距、碰撞）写不等式检查。
  2. 大模型（上千个面）的成本在于每个特征和整体做布尔运算。后续还需要**特征级缓存**和**装配**（各零件独立检查）来降低成本。
